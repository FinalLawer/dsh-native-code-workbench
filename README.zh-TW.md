# DSH Code Workbench

[简体中文](README.md) · [English](README.en.md) · **繁體中文**

為 DSH Web GUI 的右側欄加上一個 **VS Code 風格的程式碼工作台**：用 **Monaco（VS Code 編輯器核心本體）** 瀏覽與編輯工作區檔案——語法高亮、多游標、尋找、復原，全部與 VS Code 同款。在此之上還有程式碼庫檢索、Tab 補全、儲存檢查點與還原，以及把程式碼加進對話。

**設計原則：只組合官方機制，不自建平行協定。** 寫入走官方 Connection 通道 + `ctx.fs`，讀取走官方 `workspaceFiles` Remote，預覽交給官方文件預覽，對話引用走官方 chip 通道。外掛自己不發明任何協定、不複製任何登錄表。

## 安裝

在 DSH 側邊欄的**外掛**頁點**新增外掛**，把下面任一個填進對話框，裝完點**立即啟用**。已安裝但沒啟用的組合包，之後也能在外掛頁開啟。

### 從 npm 安裝（最省事）

```
dsh-code-workbench
```

需要固定版本時帶上版本號：

```
dsh-code-workbench@0.6.2
```

### 從 GitHub 安裝

```
https://github.com/FinalLawer/dsh-native-code-workbench#path:/dsh-code-workbench
```

固定版本請把 tag 一起帶上：

```
https://github.com/FinalLawer/dsh-native-code-workbench#v0.6.2&path:/dsh-code-workbench
```

⚠️ **`#path:/dsh-code-workbench` 這一段不能省。** 這個儲存庫的根目錄不是套件——外掛在 `dsh-code-workbench/` 子目錄裡，根目錄沒有 `package.json`。省略它時 pnpm 仍會回報安裝成功，但裝出來的是一個名為 `dsh-native-code-workbench.git`、版本 `0.0.0` 的佔位套件（清單是 pnpm 產生的 `{"_pnpmPlaceholder": …}`），既沒有套件清單也沒有 `dsh.bundle` 宣告，DSH 讀不到組合包，外掛不會出現。這個失敗發生在安裝**之後**，光看安裝過程看不出來。走 npm 或壓縮包則沒有這個問題。

### 從壓縮包安裝

把 `dsh-code-workbench-<版本>.tgz` 放到任意位置，在同一個對話框裡填它的**絕對路徑**。三條路徑裝進 profile 的內容一致（依 `files` 白名單，20 個檔案）。

### 相依與升級

安裝需要目標機器有 **pnpm**；走 GitHub 連結還需要 **git**，npm 和壓縮包不需要。套件裡的 `client.js` 是預先建置的產物，安裝過程**不執行任何建置指令碼**，所以不會觸發 pnpm 的相依指令碼攔截。

**升級**：官方安裝器只提供安裝與移除，沒有 `update` 子命令；外掛內建「檢查更新 / 一鍵升級」（見下文「目前能力」）。手動升級也可以把新連結直接貼進安裝框按 Enter——對同名外掛的攔截只比對**裸套件名**，帶完整 URL 不會被攔。對外散佈建議帶 tag 或版本號，而不是跟著最新 master。

## 工作台版面

左側圖示列切換檔案、搜尋與歷史檢視，再點一次目前檢視可收合導覽。檔案樹頂端提供新增檔案、新增資料夾、重新整理和全部收合。編輯區顯示多檔案分頁和目前檔案的路徑導覽，配色與控件跟隨 DSH 主題。

在檔案樹裡點空白處會清空選取；頂端的新增按鈕於是回到「在工作區根目錄建立」，選取某個目錄時則改為在該目錄中建立。檔案樹只給**選取**畫標記，**目前開啟的檔案在樹裡不帶任何標記**——哪個檔案開著由分頁列回答（恰好一個作用中分頁）。編輯區的分頁可以拖曳：在分頁列內左右拖可以換位，拖進主對話輸入框則落成一枚引用膠囊（與拖檔案樹列同形）。

每個開啟的檔案保留獨立編輯內容、復原記錄和游標／捲動位置，切換分頁不遺失未儲存的修改。分頁上的圓點表示未儲存；關閉時可確認捨棄或取消後儲存。開啟自動儲存後，切換檔案也會儲存原檔案。重新命名、移動或刪除前必須先儲存受影響的開啟檔案；分頁隨後同步更新。重新整理檔案樹會重新載入已展開的目錄。

工作台只渲染 UTF-8 文字，所以 PDF、Excel/CSV、Word/PPT、圖片這類檔案在這裡沒有可顯示的內容：點擊它們**不會開分頁**，而是把檔案位址交給右側欄的 DSH 官方文件預覽開啟（狀態列會說明檔案去了哪裡），右側欄因此多出一個預覽分頁，可與「程式碼工作台」並排。若目前環境沒有註冊能認領該位址的預覽實作，工作台退回自己的錯誤提示並註明該去哪看，不會假裝開啟過。

## 檔案樹右鍵選單

在檔案、目錄或檔案樹空白處按右鍵，可以新增檔案和資料夾、在檔案總管中顯示、加入路徑引用到目前對話、開啟工作區終端機、剪下／複製／貼上、複製路徑、重新命名及刪除。新增和重新命名使用工作台內的名稱對話框，刪除使用確認對話框。剪下和複製後，在目標資料夾按右鍵選擇貼上；複製遇到同名檔案會自動產生不同的名稱。「加入路徑引用」或把檔案樹列拖進輸入框會落成一枚引用膠囊，傳送時展開為與官方 `@` 引用同形的 **`@路徑` mention**（目錄帶尾斜線）：對話記錄裡因此渲染回同一個膠囊、點按在右側欄預覽，Agent 則依系統提示裡那條 `@` 指引先讀再下結論。檔案操作要求工作階段允許工作區寫入，禁止覆寫既有目標和修改工作區外路徑；刪除需要確認且不能復原。

**選取只由使用者放下**：點擊（左鍵）檔案樹的空白處會清空選取。落在列上、列內控件、工具列（包括工具列自己的空白）或輸入框裡的點擊不算空白——否則「選取一列」和「清空選取」會重合成一個手勢，而選取目錄後往右上走點「新增檔案」的擦邊點擊會先把目標打回根目錄。清空後頂端新增按鈕回到在工作區根目錄建立；目前開啟的檔案不受影響（選取是「操作目標」，不是「正在看的檔案」）。

「在資料夾中尋找」仍然沒有。選單不包含執行測試、偵錯測試、執行覆蓋率測試，目前未加入「加入至新對話」。

「開啟工作區終端機」這個入口**曾經被移除**（當時沒有可用的官方通道），現在回來了。它呼叫右側欄導覽控制器的 `openTab('terminal')`，在右側欄開啟**官方終端機**分頁——與該面板內建 `+` 選單裡的「新增終端機」是同一個 kind（kind 是 `terminal`；`dsh-client-ui-sidebar-terminal` 是**套件名**，把它當 kind 傳會拋錯且什麼都開不出來）。開的是官方終端機本身，shell、工作目錄、PTY 全歸那個套件，所以它**只開啟終端機，不代跑任何指令**：點哪一列都不影響終端機的工作目錄（終端機從工作階段工作區啟動），選單標題因此寫「工作區終端機」而不是「在此處開啟終端機」。若目前環境沒有註冊終端機面板，選單會明確回報「無法開啟終端機：宿主未提供終端機面板」，不會假裝開過。

## Tab 補全（僅 FIM）

Tab 補全走 **FIM（fill-in-the-middle）**：游標前的程式碼作 `prompt`、游標後的程式碼作 `suffix` 一起交給補全端點，伺服器端補出中間一段。沒有提示詞、沒有對話框架，返回的就是程式碼本身，貼合度最高。

請求形態固定，**一次請求一次回應，不串流**：

```
POST {baseUrl}/completions        # baseUrl 已以 /completions 結尾則原樣使用
{ "model": …, "prompt": "<游標前>", "suffix": "<游標後>", "stream": false, "temperature": 0.2, "max_tokens": 128 }
```

⚠️ **`suffix` 這個鍵必須始終存在，即使它是空字串**。DeepSeek 依請求主體的**形狀**分流：一旦這個鍵消失，請求就不再被當成 fill-in-the-middle，而是退化為普通續寫——模型於是接著寫自己的訓練資料（CSDN 教學頁的「时间: … 浏览: …」、markdown 圍籬那一整套），而不是寫程式碼。實測同一提示詞的 A/B：省略該鍵 **0/4 乾淨**，明確傳空字串 **8/8 乾淨**。所以游標在檔案末尾（後綴為空）時走的是 `"suffix": ""`，不是不發這個欄位。

**為什麼不用串流**：ghost text 只會以「完整建議」的形式出現——Monaco 的 inline-completions provider 只答覆一次，無法修訂已經返回的結果——所以漸進渲染拿不到任何收益，反而要多養一個 SSE 解析器和一套幀協定。實測兩者在雜訊範圍內沒有差別。真正佔時間的是**首位元組（TTFT）**，400–800ms 的網路 + 伺服器端排隊，用戶端改不動。

回應對 `choices[0]` 依序識別 `text`、`message.content`、`delta.content` 三種欄位，因此 DeepSeek 之外的相容服務也能直接用。請求帶 10 秒硬逾時；打字打斷會立即中止在途請求。

觸發的主體是 Monaco：它在每個輸入字元（含空白鍵）、退格／刪除、Tab、貼上上都會自己發請求。外掛自己只補一種 Monaco 不問的情形：**游標落點**（滑鼠點進某行、方向鍵挪過去）——停穩 250ms 後經 `onDidChangeInlineCompletions` 頻道問一次，打字拖過去的游標移動、繪製選取範圍中的落點、程式自己挪的游標都不算。此前外掛在內容變更後 400ms 會自己發一次 `editor.action.inlineSuggest.trigger`，而那是 **Explicit** 觸發，不滿足已在途的 Automatic 請求——Monaco 會丟掉在途那次並重開一次，於是每次補全都多一個來回、固定多等 400ms；更糟的是每多敲一個字終點就再後退 400ms，表現就是「要打個空白鍵或刪一下才會出來」。

同一游標的並行請求現在共用一次來回：第二次詢問 await 第一次的答案並優先讀快取，而不是回 `{items: []}`——空陣列對 Monaco 不是「我不知道」而是「這一版沒有建議」的判決，被記進 state 後後續詢問會被短路，於是必須再動一次鍵盤才解鎖。

**空行上的補全**：游標停在空行（或只含縮排的行）上時，模型經常回「先換行再縮排再寫程式碼」——那是它在行尾的慣用續寫，可空行本來就已經是新行，多出來的那一次換行會讓 ghost 的第一行只剩下空白或縮排、按 Tab 也只插入一個換行加縮排。外掛在空行上把這段冗餘的前導空行折掉，讓程式碼落回本行（與 Cursor 在編輯落在行邊界時剝掉前導 EOL 同一處理）；折完仍然只剩空白的答案照舊當作「沒有建議」。行尾游標上的「換行 + 縮排」是正確答案，原樣保留。

### 設定項

在 DSH 設定的「程式碼工作台」裡：

| 設定 | 預設值 | 說明 |
|---|---|---|
| 啟用 Tab 補全 | 開 | 關掉後按 Tab 只說縮排，不發請求 |
| 補全端點位址 | `https://api.deepseek.com/beta` | 自動補 `/completions`；也接受完整端點（如 `https://api.mistral.ai/v1/fim/completions`） |
| 補全模型 | `deepseek-flash` | 該端點只接受 `deepseek-flash` 與 `deepseek-v4-pro`，兩者都支援 FIM |
| 補全 API Key | 空 | 秘密欄位，留空時不顯示、不回顯；填了就是最高優先權的憑證 |
| 編輯自動儲存 | 關 | 開啟後停頓 900ms 自動儲存 |

設定頁頂端有一塊 **「目前補全鏈路」**，實際展示請求會落到哪個端點、哪個模型、用的是哪一路憑證——不用猜為什麼沒補全。

### 憑證優先順序

依序嘗試，第一個可用的勝出；**任何一路都不可用時不報錯，只是沒有 ghost text**：

1. **設定頁填寫的 API Key** → 送出 `Authorization: Bearer <key>`
2. **DSH 憑證庫裡名為 `DEEPSEEK_API_KEY` 的那條**（`$DSH_HOME/.credentials.yaml` 的 `refs`，同名的環境變數也算）→ 同樣是 `Bearer`。散佈出去時對方機器上**只要他自己設過這個 key，就完全不用碰設定頁**。
3. **DSH 登入帳號的憑證授權**（`records.deepseek-account-platform/*`）→ **不送 `Authorization`**，改送 DSH 私有標頭 `x-dsh-auth-token`。僅當目標位址的 **origin** 屬於該帳號服務信任的推理來源（預設 `https://api.deepseek.com`）時才會簽發。

API Key 透過 Host 設定服務儲存，標記為秘密欄位，設定頁不會回顯。金鑰輸入框留空保留原金鑰。

### 失敗時靜默

端點位址不合法、找不到憑證、上游拒絕（401/403/5xx）、網路逾時——這些**都不會彈錯**：Host 半邊記一條 `logger.warn`（含端點、模型、憑證來源），回給編輯器的是**一個正常的 200 回應、只是 `text` 為空**，編輯器不顯示任何 ghost text，也不彈任何錯誤。只有請求主體本身格式錯誤（即我們自己用戶端半邊壞了）才會返回 400。

編輯器狀態列會寫一行結果：`AI 补全生成中…` / `Tab 接受 AI 建议` / `AI 未返回补全` / `AI 补全已取消`，便於現場判斷到底走沒走通。

所以排查補全完全不工作時，看 **DSH 主機日誌**裡的 `code-workbench: completion skipped — …`（那行帶端點、模型和憑證來源），狀態列只告訴你「本地這一側認為發生了什麼」。

## 目前能力

| 能力 | 實作 | 機制 |
|---|---|---|
| 編輯器 | **Monaco 內嵌**（約 5.13 MiB bundle，延遲載入） | `monaco-editor` 打進 bundle（瀏覽器模組表凍結，沒有 Monaco，必須內嵌） |
| Worker | Blob URL 內嵌 `editor.worker` | `self.MonacoEnvironment.getWorker`，無 CSP 攔截 |
| 檔案樹 | 遞迴、延遲展開 | `ctx.remote.workspaceFiles.list`（官方唯讀 Remote） |
| 讀取檔案 | 分頁讀全量、依副檔名選語言 | `ctx.remote.workspaceFiles.read`（依行分頁，`eof` 收尾） |
| **非文字檔案轉交** | 點擊 PDF / Excel / Word / PPT / 圖片等非文字檔案 → 不建模型、不開自家分頁，改在右側欄「文件預覽」中開啟 | 官方 `fileAddressFor`（`@deepseek-ai/dsh-util-workspace-path`）+ `ctx.sidebarRight.openResource`，落到官方 `dsh-resource://file/**` 預覽檔位；本外掛分頁類型不註冊 pattern，因此不搶官方 fallback |
| **寫入檔案** | `POST /api/code-workbench/write`，**版本守衛**（`FS_STALE_VERSION` 拒絕覆寫並行修改），沙箱策略 = 工作階段標準策略 | host 半邊 `ctx.connection.fetch.register`（與官方 `/api/file` 同一通道）→ `ctx.fs.writeText(target, text, intent, signal, sandboxPolicy)` |
| **程式碼庫檢索** | 左欄「搜尋」模式：正規表達式／大小寫搜尋、結果清單、點擊跳至該行並高亮 | `POST /api/code-workbench/search`：`ctx.fs` 有界走訪（忽略 `node_modules`／二進位副檔名）+ 行比對，檔案數／符合數／時間三重預算 |
| **@codebase（Agent 工具）** | 對話裡的 Agent 內建 `codebase_search` 工具：自然語言多詞**排序檢索**，返回 top 片段（補官方 `grep` 的精確正規表達式） | `ctx.tools.register`（官方 Tool Runtime）+ 同一檢索核心（terms 模式 + 詞覆蓋率排序） |
| **Tab 補全** | 打字停頓 180ms 後灰色 ghost 建議，**Tab 接受**、繼續打字即取消；同一時刻最多一個請求 | Monaco `registerInlineCompletionsProvider`（ghost 渲染／接受全是內建）+ `POST /api/code-workbench/complete`（**純 FIM、非串流** `prompt`／`suffix`，128 token 預算，憑證三級備援，10s 硬逾時；失敗靜默）+ `POST /api/code-workbench/completion-status`（唯讀，回報實際鏈路） |
| **檢查點／還原** | 每次儲存自動入帳本；左欄「歷史」列出檢查點，**一鍵還原**到任意儲存之前；還原本身也是檢查點，可再還原 | `POST /api/code-workbench/history` / `rollback`（host 記憶體帳本，每檔案 20 條、每側 200KB 上限）+ `ctx.fs.writeText` 版本守衛 |
| **檢查更新／一鍵升級** | 有新版本發佈時面板頂端出現提示列，點「升級」原地取代安裝目錄裡的檔案；只動了**執行期不參與啟動載入**的檔案（`client.js`，以及 `src/*` 建置輸入、`build.mjs`、README 等）就**免重啟**——`client.js` 由 HMR 自己重載面板；改了 Host 半邊啟動時載入過的檔案（`index.js` 及其 import）才提示「重啟 DSH 後生效」 | `POST /api/code-workbench/update-check`（`api.github.com` REST：`/tags` → 該 tag 的 `update.json` → 與本機逐檔摘要比對）與 `POST /api/code-workbench/update-apply`（每個檔案先依清單摘要驗證、再 `rename` 原子取代） |
| **外部變更自動重載** | Agent／外部改了磁碟上的檔案 → 乾淨緩衝區**自動重新整理**；有未儲存修改時警告不覆寫 | 官方 `workspaceFiles.changes` 串流（`ctx.remote.$stream`），依開啟檔案訂閱 |
| **加入對話（Add to Chat）** | 右側欄**選取多行程式碼** → `Ctrl+L`、右側欄按鈕、或**編輯器右鍵選單「加入至對話」** → 主對話輸入框裡出現**引用膠囊**（只顯示 `檔案:行號 · N 行`），**傳送時才展開**成完整程式碼區塊給 Agent | 官方 chip 機制：`slash/input-insert-reference` 事件插 `ReferenceChipNode` + 自註冊 reference codec（`inputTriggers.registerSource` 的 `codec.serialize` 做提交展開）。三個入口進的是**同一個** `addToChat`，所以產出同一枚膠囊；右鍵選單項由 `editor.addAction` 註冊在 cut/copy/paste 群組之後，**不帶** `keybinding`（`Ctrl+L` 已由 `addCommand` 註冊，重複註冊同一個組合鍵是靜默的）也**不帶** `precondition`（本 build 未定義的 context key 恆為 false，會把選單項永久變灰，看起來像壞了） |
| **選取懸浮膠囊** | 在編輯器裡選取程式碼，選取範圍附近浮出「**加入至對話、Ctrl+L**」膠囊，點一下即加入對話；選取消失即收起，正在顯示 ghost 建議時讓位 | Monaco **內容部件**（`editor.addContentWidget`）—— 膠囊只給出行列錨點，像素位置由 Monaco 自己算。落點搜尋照 Cursor 的演算法複刻（在 ±2 行視窗裡挑最長的一行作錨，代價 = 行長與 5 行之差 + 25 × 行偏移），但**偏好恆為 `EXACT`**、上下偏移由外掛自算 `transform`：Monaco 的 `ABOVE`/`BELOW` 以**整個視窗**為鉗制基準，而編輯器只占右欄一條 |
| **拖曳列到輸入框** | 檔案樹列（檔案或目錄）拖進主對話輸入框 → 落成引用膠囊；**傳送時展開為共用 `@路徑` mention**（目錄帶尾斜線、含空格走 `@"…"`），對話記錄裡渲染回同一個膠囊 | 私有 MIME「三重收窄」在 document 捕獲階段接管拖放 → 同一個官方 `slash/input-insert-reference` 通道；提交展開走同一個 reference codec（`clipboardText` 與展開文案逐字一致） |
| **拖曳分頁** | 分頁列上的分頁同樣可拖：拖進主對話輸入框 → 與拖檔案樹列**完全相同的引用膠囊**；在分頁列內左右拖 → **換位**，落點那一側的邊緣出現插入標記 | 重用同一個私有 MIME 和同一個官方通道，因此膠囊只有一個出處；列內換位由各自的 drag ref 分流——**兩個手勢互不認領**（樹列拖過分頁列不換位，分頁拖到資料夾列也不移動檔案） |
| **點空白處取消選取** | 點擊檔案樹空白處 → 清空選取；頂端新增按鈕隨之回到在工作區根目錄建立 | 樹的容器 `onClick`，用 `closest('.code-workbench-tree-row, button, input, .code-workbench-tree-toolbar')` 排除落在列、列內控件和工具列上的點擊：列點擊本來就會冒泡到容器，而工具列是右對齊的，**選取目錄後的下一個動作就是往右上走點「新增檔案」，擦邊落在它的空白處**——沒有這道守衛時，兩個手勢會重合成一個，近失手又會把目標悄悄打回根目錄。清空 `selected` 的同時一併清掉 Shift 多選集合與錨點 |
| **樹只標記選取** | 檔案樹裡只有**選取**（新增按鈕的落點、右鍵選單與拖曳的作用目標）會畫底色 + 細框；**目前開啟的檔案在樹裡零標記** | 一次點擊會**同時**開啟檔案並把它設為選取，兩種狀態疊在同一列：給它任何標記都會被讀成「選取標記的一部分」——兩個畫得一模一樣的框就是「取消不掉的框」，框上再疊一根豎條就是多了一個東西。哪個檔案開著由分頁列回答（恰好一個作用中分頁），樹不回答第二遍。`:hover` 保留——那是游標自己的瞬時回饋，不掛在任何狀態上 |
| 可追溯 | 每次儲存記 Session 備註 | `sessionFeedback.record` |
| 主題 | 跟隨 DSH 明暗主題 | `body[data-ds-dark-theme]` MutationObserver → `monaco.editor.setTheme`；調色盤取自 `--dsw-alias-*`，但**先正規化為 `#RRGGBB[AA]` 再交給 Monaco**——它的主題解析只認 hex 拼寫，認不出的值不會報錯，而是靜默塗成純 `#ff0000` |
| 快速鍵／編輯器右鍵選單 | `Ctrl+S` 儲存、`Ctrl+L` 將選取程式碼加入對話、`Tab` 接受補全（編輯器內）；編輯器右鍵選單另有一項「加入至對話」 | `editor.addCommand`（快速鍵）+ `editor.addAction`（選單項，註冊在 cut/copy/paste 群組之後） |

## 組成與實作

外掛由**兩個半邊**構成，DSH 分別載入：

| 半邊 | 原始碼 → 產物 | 職責 |
|---|---|---|
| Host | [`index.ts`](dsh-code-workbench/index.ts) → `index.js` | 版本守衛寫入、檔案操作、檢索、Tab 補全、檢查點與還原、檢查更新與升級，以及 `codebase_search` 工具 |
| Client | [`src/client.ts`](dsh-code-workbench/src/client.ts) → `client.js` | 右側欄分頁 `code-workbench`：檔案樹 + Monaco + Tab 補全 + 程式碼引用 |

**為什麼用戶端半邊必須內嵌 Monaco。** DSH 的用戶端模組執行環境把每個外掛當一段自包含的指令碼載入，工廠裡只允許 `require` 基準模組表（`react` 等），Monaco 不在表裡。所以 `client.js` 是把 Monaco、它的 worker 和全部 CSS 打包在一起的單一檔案（約 5.13 MiB，延遲載入）——worker 轉成 Blob URL 注入，CSS 轉成 `<style>`。這條契約是硬限制，不是取捨。

**為什麼 Host 半邊不打包。** 安裝後的 `index.js` 是排障時唯一能讀的東西，所以它由 `tsc` 逐檔轉譯、**保留全部註解**，而不是交給 esbuild（後者會剝掉所有註解）。型別錯誤會直接讓建置失敗，不會進入產物。

**原始碼與產物同名同目錄。** `index.ts` → `index.js`、`src/client.ts` → `client.js`，原始碼就放在它產出的東西旁邊。少數原始檔用 `.mts` 副檔名，因為 `index.ts` 裡必須逐字寫 `./completion-api.mjs`——那是**產物**的真實名字，而 TypeScript 的副檔名替換規則裡 `.mjs` 只對應 `.mts`。

**SDK 的型別是手寫的。** DSH 用戶端 SDK 的每個套件都在 `package.json` 裡宣告了 `types` 路徑，但**套件裡並沒有那些檔案**，所以 `types/` 下是這個外掛真正呼叫到的那部分宣告，範圍刻意收窄——試圖涵蓋整個 SDK 只會得到它的一份無法驗證的副本。

## 已知限制

- 檔案同步使用官方 changes 串流，並每 1.5 秒檢查開啟檔案版本、視窗重新聚焦時檢查；乾淨緩衝區自動重讀，未儲存修改保留。
- 新傳送的程式碼引用在對話記錄中預設收合為檔案與行號，點擊展開；模型仍收到完整選取範圍。此前傳送的普通程式碼區塊沒有引用標記，保留原展示。
- 路徑引用（右鍵「加入路徑引用」或拖曳檔案樹列）在對話記錄裡是與輸入框同形的膠囊，點按在右側欄預覽——因為提交時展開的就是官方 `@路徑` mention，官方投影再把這段文字裝飾回膠囊。目錄膠囊只作展示：官方投影只給檔案接跳轉。
- 非文字檔案（PDF、xlsx/xls/csv/tsv、doc/docx/ppt/pptx、圖片等）不在本面板渲染：工作台只把檔案位址**轉交**給右側欄的官方文件預覽，因此它們的分頁不會出現在「程式碼工作台」裡。轉交依據是讀取失敗的錯誤碼（`workspace-file/not-text` / `too-large`），**不是副檔名白名單**——能渲染哪些副檔名由官方預覽自己的登錄表擁有，這裡不複製一份。若目前環境沒有註冊能認領該位址的預覽實作（`openResource` 會拋錯），工作台保留自己的錯誤提示並註明該去哪看，不會回報一個它沒能開啟的檔案。
- 更新讀的是 `api.github.com` REST 端點（`/tags`、`/contents`、`/git/blobs`），不走 raw 內容網域——後者在部分網路下不可達。儲存庫沒有 Release 物件，所以版本從 **tag 清單**裡取：這裡自己依 semver 排序（`/tags` 不承諾順序），取最高的那個帶 `update.json` 的 tag，因此本功能之前發佈的 tag 會被逐個跳過而不是讓整次檢查失敗。GitHub 不可達、儲存庫裡沒有清單、本地已是最新——三者對面板都只有一個答案：不顯示任何東西。**從 npm 安裝的副本同樣靠 GitHub 上的 tag 檢查更新**，因為清單是隨儲存庫發佈的。
- 升級只寫**本套件自己的安裝目錄**，不觸碰工作區。清單裡出現絕對路徑、`.`／`..` 段、反斜線或空段會被直接拒絕；檔案數上限 64、單檔上限 32 MiB、清單上限 256 KiB。
- 取代是**逐檔**的 `rename`：一個檔案失敗不影響已經落地的那些，失敗時留下的是「逐個都合法但版本混合」的樹，而不是寫壞的檔案。驗證用的是發佈方在清單裡給出的摘要（用 `rename` 而不是直接寫，是因為安裝樹裡每個檔案都是 pnpm 硬連結到內容庫的，寫穿會改到其他 profile 共用的那份）。
- ⚠️ 若某次更新提示「重啟 DSH 後生效」而使用者沒有重啟就關掉了面板：**不會**再次提示——`installedVersion()` 讀的是磁碟上的 `package.json`，而那時磁碟上已經是最新版了。這是刻意的（磁碟上版本就是已安裝版本，不製造「永遠提示有更新」的假訊號），代價是這次提醒是一次性的；下次啟動 DSH 會讓新版本全面生效。
- 免重啟的判定只看 `client.js` / `package.json` 是否在變更之列；只要發佈裡動了 Host 半邊載入過的檔案（`index.js`、`completion-api.mjs`、`vendor/schemastery.mjs`、`src/completion-window.mjs`、`cordis.patch.yml`），就提示重啟——那些程式碼行程已經載入在記憶體裡，取代檔案本身不足以讓它們生效。
- 拖放的兩個手勢共用同一個私有 MIME，靠各自的 drag ref 分流，所以**跨手勢不生效**：把分頁拖到檔案樹的資料夾列上不會移動檔案，把檔案樹列拖過分頁列也不會換位。要移動檔案請用樹內拖放或右鍵剪下／貼上，要換位請在分頁列內拖。
- 檔案樹的「選取」和編輯區的「目前檔案」是兩件事：清空選取不會關閉任何分頁；從**分頁列**開啟一個檔案也不改變樹裡的選取。但**在樹裡點一列會同時把該列設為選取**（新增按鈕的落點始終跟著選取走），所以點開一個檔案後那一列帶的是**選取**標記，不是「目前檔案」標記。樹裡不給目前開啟的檔案畫任何東西。選取的目錄不會被自動展開。
- Tab 補全採用 180ms 請求防抖、較小的前後文（前綴 3200 字元／後綴 900 字元）和 128 token 預算，並快取最近 40 個游標上下文。⚠️ **本機網路抖動實測 ±300ms，比大部分參數效應還大**——任何「變快了」的判斷都要多輪取樣才作數，單次測量沒有意義。
- 憑證第三級（DSH 帳號授權）已**對真實 `/beta/completions` 端點驗證通過**（HTTP 200，用私有標頭 `x-dsh-auth-token`、不帶 `Authorization`）。注意它只在 **origin** 屬於該帳號服務信任的推理來源時才會簽發。
- bundle 5.13 MiB（Monaco 核心 minify 後 + 常用 28 種語法 + JSON 語言服務）；首次開啟面板時解析（延遲載入）。
- TS/JS 語意智慧未啟用（砍掉了 12MB 的 TS 語言服務）：TS/JS 有語法高亮 + 編輯器全套功能，但沒有語意診斷／跳轉；補全為詞級 + AI ghost text。
- 單檔讀取受官方 `workspaceFiles` 上限約束（預設 2 MiB／5000 行一頁，最多 40 頁）。
- 檢查點帳本在 host 記憶體（每檔案 20 條）：重啟 DSH 後歸零。
- 「語意檢索」為詞覆蓋率排序的詞彙檢索（DeepSeek API 無 embeddings 端點，無法做向量語意）。
